# Contributing

## Workflow

- Work on one issue per branch, named `issue-<number>-<short-slug>`.
- Keep each pull request focused on its issue and include the issue number in commits or the PR description.
- Follow the existing commit style (`feat:`, `fix:`, `chore:`, `docs:`, `test:`).
- Do not add product features that are not in an issue.

## Before opening a pull request

- Run backend tests and frontend tests/build for the code you changed.
- Update documentation and `.env.example` when behavior or configuration changes.
- Check that no secrets or generated files are included.
- Complete the pull request checklist.
